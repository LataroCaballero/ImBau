This plan resolves the media+idempotency tension flagged in CONTEXT (D-04 / Claude's Discretion): `registerAndEnqueue` mints a `randomUUID` (`register.ts:52`) and would duplicate rows + R2 objects on re-run — so the seed does NOT call it and does NOT import `@imbau/api` (db-api package cycle). It re-composes the `@imbau/storage` primitives with a deterministic `mediaId` + `onConflictDoNothing`. The locked intent of D-04 (real pipeline end-to-end, no pre-baked media rows) is fully preserved; only the delegated mechanism is resolved per RESEARCH Pattern 2.
Output: A seed run (with R2 + worker up) that leaves brokers/leads/progress/galleries/events populated and every seeded media resolvable with real variants — idempotent across re-runs.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| seed process to R2 (S3 PutObject) | Original bytes land at a deterministic server-derived key; use makeR2Client (CRC32 opt-out), never a bare client |
| seed process to Redis/BullMQ | Media jobs enqueued with jobId=mediaId; dedup guarantees no duplicate processing |
| seed process to Postgres (app_authenticated via withTenant) | All content + media rows; RLS `*_tenant` withCheck (org = GUC) applies |
| committed image bytes to worker | Untrusted-ish binary; the worker re-encodes via sharp, stripping most embedded payloads |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-04 | Tampering (Input Validation) | leads.timeline JSONB | medium | mitigate | Validate every LeadNote[] with `leadNoteSchema.parse` before insert (ASVS V5) — even seed data passes the boundary validator |
| T-03-05 | Tampering | committed stock image with hidden payload | low | mitigate | Reputable stock sources (Unsplash/Pexels/CC0); the worker's sharp re-encode strips most embedded payloads |
| T-03-06 | Information Disclosure | R2 keys/secrets in logs/errors | medium | mitigate | Report var NAMES only in fail-fast; never log R2 keys/secrets or object bodies |
| T-03-07 | Elevation/Tampering | media/content rows via owner | high | mitigate | All media + content rows via `withTenant`; owner used only for the org root + events partition DDL (created in plan 01 scaffold) |
| T-03-08 | Tampering | non-deterministic media (randomUUID) duplicating rows/objects on re-run | high | mitigate | Deterministic mediaId + onConflictDoNothing + jobId=mediaId dedup + deterministic keys (overwrite in place); explicitly do NOT call registerAndEnqueue |
</threat_model>
