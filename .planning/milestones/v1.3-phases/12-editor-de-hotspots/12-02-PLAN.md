<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| panel/browser → hotspots tRPC | Untrusted caller: may be unauthenticated, a viewer, or an owner of another org; may send a malformed/oversized polygon payload. |
| client `isValid` → server | The client pre-validates for UX, but that flag is untrusted — the server is the authority. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-12-01 | Spoofing/Elevation | unauthenticated write to any hotspots mutation | high | mitigate | All writes build on `requireRole` which extends `protectedProcedure` — no session → UNAUTHORIZED before any DB access. |
| T-12-02 | Elevation of Privilege | authenticated VIEWER writes a polygon | high | mitigate | Explicit `requireRole("owner","developer")` rejects the viewer with FORBIDDEN BEFORE the UPDATE — RLS alone would let a viewer write (the load-bearing Phase 9 lesson); proven by the viewer case in the matrix test. |
| T-12-03 | Tampering/Info-disclosure | cross-org write (owner of org B targets org A floor/unit) | high | mitigate | `withTenant` + `.where(id ∧ projectId)` + `.returning()` 0-row → NOT_FOUND; the row is invisible under RLS so the write is a no-op turned into a no-enumeration NOT_FOUND; proven by the other-org case. |
| T-12-04 | Denial of Service | oversized polygon payload / O(n²) self-intersection on a huge vertex list | medium | mitigate | `poligonoSvg` Zod input length-capped; vertex count capped (≈200) → BAD_REQUEST before the O(n²) validation runs. |
| T-12-05 | Tampering/Injection | arbitrary string persisted then rendered by phase-2 as `<polygon points>` | medium | mitigate | Server re-runs `parsePolygon` (integer pairs 0-1000 only) then persists `serializePolygon(points)` — only canonical integer pairs ever reach the DB; no arbitrary string survives. |
| T-12-SC | Supply chain | npm installs | low | accept | No net-new package-manager installs this plan. No `[ASSUMED]`/`[SUS]` packages → no legitimacy checkpoint. |
</threat_model>
