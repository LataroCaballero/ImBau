<objective>
Endurecer el job de media para MEDIA-04: idempotencia, reintentos y errores observables, sin dejar nunca la media en estado inconsistente. Tres frentes: (1) **observabilidad del fallo** — un handler `failed` que enruta a Sentry + pino (nunca un catch silencioso), factorizado como `reportMediaFailure` para que sea testeable sin Redis; (2) **pruebas de integración contra Postgres 16 real** que PRUEBAN las tres garantías de MEDIA-04: idempotencia (correr processMedia dos veces → keys idénticas, una fila, mapa idéntico), recuperabilidad ante fallo (inyectar fallo → la fila queda `variants={}`, re-ejecutable) y el role-guard del write-back (corre como `app_authenticated` + GUC, no owner/BYPASSRLS); (3) el **checkpoint humano de provisioning de R2** que gatea el smoke real end-to-end en staging (CI usa mock S3, nunca un R2 real).

Decisiones bloqueadas que materializa este plan: **A1** (sin estado parcial — la única UPDATE final de 02-02 hace la recuperabilidad demostrable), **A8** (write-back como app_authenticated, probado por el role-guard), e **idempotencia** (variantKey determinista + jobId=mediaId + attempts/backoff de mediaJobOptions + handler failed → Sentry/pino).

Purpose: sin estas pruebas y la observabilidad, MEDIA-04 ("idempotente, con reintentos, errores observables, nunca inconsistente") queda sin cubrir; el smoke real cierra el lazo en staging una vez provisto R2.
Output: reportMediaFailure + wiring del handler, el harness de integración del worker (migrate + role-guard + fixtures), las suites de integración/fallo, y el checkpoint de provisioning + smoke de staging.
</objective>
