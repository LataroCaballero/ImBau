<objective>
Wire the two API seams that make the async PDF flow possible (PDF-01): (1) the PRODUCER — enqueue a PDF
job inside `quotes.create` (the cabling D-13 of fase 5 deliberately deferred, D-02), and (2) the STATUS
endpoint — a `quotes.pdfStatus` publicProcedure the buyer polls, which returns a short-lived presigned R2
GET once `pdfKey` exists (D-03/D-04). Both live behind a lazy-memoized `packages/api/src/quotes/runtime.ts`
cloned from `media/runtime.ts`, so importing `appRouter` never opens Redis or validates R2. The status
path derives the tenant server-side from the published project and reads `pdfKey` under `withTenant`, so
`quotes` stays tenant-private (no anon policy) and cross-tenant reads are impossible.

Purpose: This is the server contract the worker (wave 2) fulfils and the web UI (wave 2) drives. It is
independent of the worker code — both sides share only the already-coded queue contract.
Output: `quotes/runtime.ts` (enqueuePdf + presignPdfGet), `quotes.ts` (enqueue in create + pdfStatus), extended router test.
</objective>
