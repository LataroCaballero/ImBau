<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser draw affordances → server | The visible draw/save/delete controls are cosmetic; the server `requireRole` (Plan 02) is the authority. A viewer must not be able to persist a change even if the UI is tampered with. |
| render URL prop → client | The RSC builds public render URLs server-side; the client receives a URL string, never a storage key or credentials. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-12-02 | Elevation of Privilege | viewer uses draw/save affordances | high | mitigate | `canWrite` hides affordances cosmetically (defense-in-depth), but the authority is the Plan 02 `requireRole("owner","developer")` on every mutation — a tampered viewer client still gets FORBIDDEN. Manual-verify step 6 confirms the read-only view. |
| T-12-05 | Tampering/Injection | polygon string sent to the mutation | medium | mitigate | The client serializes via `serializePolygon` (integer pairs 0-1000); the server re-parses + re-validates + re-serializes (Plan 02), so a hand-crafted client payload cannot persist an arbitrary string. |
| T-12-06 | Information disclosure | R2 render URL construction | low | accept | Renders are public-served (A6, no signed GET); the URL is a public asset path built server-side from `R2_PUBLIC_BASE_URL` — no secret reaches the client. |
| T-12-SC | Supply chain | npm installs (icons) | low | mitigate | No net-new runtime dependency: inline SVG glyphs instead of lucide-react. If an icon lib is later desired it must pass the package legitimacy gate. |
</threat_model>
