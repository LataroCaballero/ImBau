## Trust Boundaries

| Boundary | Description |

| worker/api process → Resend API | outbound email egress with a verified sender |
| enqueue → Redis | job payload (ids only) crosses into the queue |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-11-03 | Information Disclosure | Resend dispatch + dev console log | medium | mitigate | Dev fallback logs only the public lead summary (to/nombre/origen), never the API key; error surfaces Resend's own message (no key); env read via t3-env (prints NAME, never VALUE). |
| T-11-04 | Spoofing | email `From` header | medium | mitigate | `from` is the verified `INVITE_FROM` sender only; required whenever `RESEND_API_KEY` is present. |
| T-11-08 | Denial of Service | notification-spam amplification | medium | mitigate | `jobId = lead:{id}:created` idempotency built into `leadEmailJobOptions` — a retried/duplicate enqueue can never stack duplicate sends. |
| T-11-SC | Tampering | npm/pnpm installs | low | mitigate | No new external packages — `resend` + `@react-email/components` already in `@imbau/api`; only a new subpath export is added. |
</threat_model>
