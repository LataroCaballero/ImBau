# Phase 11 — UI Design Contract

> Visual and interaction contract for the panel's **leads bandeja** (kanban board + lead drawer),
> the **alta-manual lead form**, the **`leadsNotifyEmail` settings field**, and the **new-lead
> notification email template**. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> This phase **inherits the panel design system established in Phase 10** (hand-rolled ImBau tokens,
> no shadcn, no component library — the token file `packages/ui/src/tokens.css` is now the settled,
> reconciled source of truth carrying palette + neutrals + type scale + radii). Phase 11 is a
> **sibling styled surface** to the units grid; it reuses the same tokens, wiring, weight system,
> and feedback pattern (inline `role="status"`/`role="alert"`, no global toast — Phase 10 D-04),
> and only specializes the **component + copy + interaction** contract for the leads surface.
>
> UI copy is **es-AR, voseo**, product tone (CLAUDE.md, brand-book §Voz). Panel is **desktop-first**
> (a data tool); the kanban degrades to horizontal scroll on narrow laptop widths.

## Typography

Inherited from Phase 10 — the same **two-weight system**: **400** for all Inter text/UI/cards/timeline
and JetBrains Mono figures; **500** for the Space Grotesk H1 only. Emphasis via size + color hierarchy
(Grafito vs Gris-500), never via weight.

| Role | Size | Weight | Line Height | Family |
|------|------|--------|-------------|--------|
| Card meta / dense (origen chip, timestamp) | 14px (0.875rem) | 400 | 1.3 | Inter |
| Lead name on card (primary card line) | 16px (1rem) | 400 | 1.3 | Inter (emphasis via Grafito color + size, not weight) |
| Body / labels / controls / note text | 16px (1rem) | 400 | 1.5 | Inter |
| Column title / drawer section heading | 20px (1.25rem) | 400 | 1.25 | Inter (emphasis via size + Grafito) |
| Figures (linked cotización id, unidad code) | 14px (0.875rem) | 400 | 1.2 | **JetBrains Mono, `tabular-nums`** |
| Page title (H1: "{Proyecto} · Leads") | 28px (1.75rem) | 500 | 1.2 | **Space Grotesk** |

Two weight values total (400 and 500). No other weights or families permitted this phase.

**es-AR display rule:** the estado enum is stored ASCII (`negociacion`, no accent) but **always
rendered with its accent**: column/label copy is `Negociación`. Never surface the raw enum value.

## Color

Panel is a light-surface data tool (brand permits: "el panel de autogestión puede ser claro").
Palette inherited verbatim from Phase 10 / `tokens.css`.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | Hormigón `#F2EFE9` (app canvas + column bodies) + Blanco `#FFFFFF` (cards, drawer, modals) | Board background and card surfaces |
| Secondary (30%) | Gris-100 `#E5E2DB` (borders, column header bg, chips) · Gris-500 `#6B7480` (meta/secondary text, timestamps) · Grafito `#14181E` (primary text) | Structure, dividers, non-primary text |
| Accent (10%) | Cobre `#D98A4F` | See reserved list below |
| Destructive / error | Vendido `#D65454` | Save/load error affordances + the `cerrado / perdido` desenlace badge (see below) |

**Accent (cobre) reserved for — explicit list (this phase):**
- Primary action buttons: `Registrar lead` (alta manual), `Agregar nota` (drawer submit),
  `Guardar desenlace` (desenlace prompt confirm), `Guardar email` (settings field).
- The **active drop-target column ring** (2px cobre) while a card is being dragged over a valid column.
- The focused-input ring inside the alta-manual form and the note textarea (2px cobre outline).

Cobre is **never** a page/large-area background, **never** a card background, **never** on the origen
chips or the pipeline-stage dots. One cobre emphasis per primary flow.

**Pipeline-stage semantic colors (reserved to column headers + card status dot + cerrado badge — NOT
part of the 10% accent).** These reuse existing brand tokens; because unit-estado colors
(disponible/reservado/vendido) do **not** appear anywhere on the leads screen, reusing green/amber/red
here creates no on-screen collision:

| Stage (enum) | Label | Dot / accent |
|--------------|-------|--------------|
| `nuevo` | Nuevo | Blueprint `#4C7DF0` (incoming / cool) |
| `contactado` | Contactado | Gris-500 `#6B7480` (neutral, in touch) |
| `negociacion` | Negociación | Reservado amber `#E3A63C` (active deal) |
| `cerrado` | Cerrado | **split by `desenlace`:** ganado → disponible green `#2FA26E` · perdido → vendido red `#D65454` |

Rendered as a filled 8px dot next to the column title and a small dot/badge on each card. The
`cerrado` column shows a per-card `Ganado` / `Perdido` badge using the split colors.

> ⚠ **Warm-color adjacency (inherited caution):** reservado amber `#E3A63C` (Negociación) and accent
> cobre `#D98A4F` are close. Mitigation: stage color appears only as a small **dot/badge** (never a
> full column fill, never a button); cobre appears only on **actions**. Stage = status, cobre = action —
> keep them visually distinct, exactly as Phase 10 separated estado dots from action buttons.

Links (breadcrumb "← Proyectos", the drawer's linked unidad/cotización deep-links): Blueprint `#4C7DF0`.

## Interaction Contracts

**Move a lead = a pipeline transition (LEADS-02, D-02, D-08).** Two equivalent paths, both writing the
same `leads.updateEstado` mutation:
1. **Drag a card** from one column to another (mouse). Drop-target column shows a 2px cobre ring while
   hovered. On drop → optimistic move → `saving` → confirmed **or** `error` (`No se pudo guardar.
   Reintentá.`; card snaps back).
2. **Estado `<select>` in the drawer** (keyboard/AT-complete). Identical mutation. This is the
   **accessibility-complete path** — drag is a mouse enhancement, never the only way to transition.

Transitions are **free** between the 4 enum values (advance, retrocede, reopen a `cerrado` — D-02).
"Máquina de estados impuesta" = the destination MUST be one of the 4 enum values; it is not linear.

**Cerrado requires a desenlace (D-03).** Any transition **into** `cerrado` (drag drop onto the Cerrado
column, or select → Cerrado) opens the desenlace prompt (`Ganado`/`Perdido`) **before** the write is
committed. Cancel → the move is aborted (card returns to origin, estado unchanged). Confirm → writes
estado=`cerrado` + `desenlace`. Transitioning **out of** `cerrado` clears/ignores `desenlace`.

**Every transition leaves a trail (D-04).** The write (a) appends an auto `LeadNote`
(`estadoPrev → estadoNuevo`, `autor` from `ctx.session`) to `leads.timeline` (the UI source of truth,
ordered by `ts`) **and** (b) emits an `events` row for the uniform audit trail (Phase 10 D-02 pattern).
Notes and transitions persist append-only in order (LEADS-03 / SC-3).

**Lead creation seeds the timeline (D-04 extended — resolved by user).** Creating a lead (showroom
capture *or* alta manual) writes a **first** `LeadNote` to `leads.timeline` (`{autor} registró el lead`
/ `Lead recibido desde el showroom`) as part of the same insert. A brand-new lead's drawer therefore
shows this creation entry — never the empty `Sin actividad todavía` state on first open; the origen is
traced from t=0. The `Sin actividad todavía` empty copy remains as a defensive state only.

**Email fires only on lead creation (D-06).** Transitions and notes do **not** notify. The alta-manual
success message asserts the email was queued (`…avisamos por email`). The enqueue is a side-effect
after a successful persist (never `await` inline in the mutation), idempotent by `jobId =
lead:{id}:created` — reintentos / re-seed / bulk never duplicate. Nothing in the UI blocks on the email.

**Drawer** opens over the board (does not navigate away, D-09) so the developer can process several
leads in a row; closing returns to the board with the card in its current column.
