# Phase 10 — UI Design Contract

> Visual and interaction contract for the panel's units grid + Excel import/export. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
> This is the panel's **highest-value, highest-risk surface (money)** and its **first styled surface** — Phase 9 shipped the shell unstyled (D-13). This contract establishes how the panel wears the ImBau brand tokens.
> UI copy is **es-AR, voseo** (CLAUDE.md). Money is **whole USD, never floats, never cents**. Panel is **desktop-first** (data tool), degrade gracefully on narrow laptop widths.

### Wiring (how the panel adopts tokens — planner/executor guidance)

The panel has **no CSS and no Tailwind today**. It must adopt the **same Tailwind v4 CSS-first + `@theme` mirror** pattern `apps/web` already established (`apps/web/app/globals.css`), not invent a new one:
1. Add `apps/panel/postcss.config.mjs` and `apps/panel/app/globals.css` with `@import "tailwindcss";` + an `@theme` block mirroring `@imbau/ui/tokens.css` (copy the `--color-*` / `--font-*` mapping verbatim from `apps/web/app/globals.css`).
2. Import `globals.css` and set the three `next/font` CSS variables (`--font-space-grotesk`, `--font-inter`, `--font-jetbrains`) on `<html>` in `apps/panel/app/layout.tsx` (today it is bare).

### ⚠ Token divergence — FLAG (reconcile, do not fork)

Two token files disagree in **naming and completeness** (hex values agree):

| File | Naming | Carries |
|------|--------|---------|
| `packages/ui/src/tokens.css` (**LIVE — apps consume this**) | un-prefixed (`--grafito`, `--cobre`) | palette + font stacks only |
| `docs/marca/tokens.css` (brand reference, **not wired**) | `--imbau-*` prefixed | palette **+ neutrals (`gris-700/500/300/100`) + type scale + radii + shadow** |

This grid needs the neutrals, radii, and type-scale tokens that **only exist in the brand file**. **Resolution:** extend the LIVE file (`packages/ui/src/tokens.css`) by adding the missing neutrals/radii/type-scale using the brand-file **values**, keeping the LIVE file's **un-prefixed naming** (`--gris-500`, `--radius-md`, …). Do NOT switch consumers to `--imbau-*`, and do NOT silently pick one file — mirror the additions into the panel `@theme` block the same way `apps/web` does.

## Spacing Scale

Declared values (standard 8-point set `{4, 8, 16, 24, 32, 48, 64}` — matches brand `docs/marca/tokens.css` base-4 rule):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gap, inline badge padding, dot-to-label gap |
| sm | 8px | Cell horizontal padding, compact control gaps, **cell content padding** |
| lg | 16px | Default element spacing, toolbar padding, **form-field gaps inside modals** |
| xl | 24px | Section padding, modal body padding |
| 2xl | 32px | Page gutter, major block separation |
| 3xl | 48px | Page-level top spacing |

The former `md = 12px` token is removed (not in the standard set). Its two usages are remapped: **cell content padding → `sm` (8px)** (horizontal cell padding, keeps dense rows tight against the 40px row height) and **modal form-field gaps → `lg` (16px)** (comfortable field separation inside modal bodies).

Grid-specific fixed dimensions (multiples of 4):

| Element | Value |
|---------|-------|
| Data row height | 40px |
| Header row height | 44px (sticky) |
| Checkbox column width | 40px |
| Min interactive cell hit target | 32px |
| Button height | 40px |
| Selection/toolbar bar height | 48px |

Exceptions: none.

## Typography

All sizes drawn from the brand type scale (`docs/marca/tokens.css`) — no invented sizes. This is a **plain two-weight system**: **400** for all text/UI/body/grid/labels/headings and for the mono money face, and **500** for the H1 display face only. Emphasis on labels and section/modal headings is achieved through **size and color hierarchy** (larger size, Grafito vs Gris-500), never through weight.

| Role | Size | Weight | Line Height | Family |
|------|------|--------|-------------|--------|
| Grid cell / dense data | 14px (0.875rem) | 400 | 1.2 (single-line, governed by 40px row) | Inter |
| **Money / figures** (price cells, diffs, m²) | 14px (0.875rem) | 400 | 1.2 | **JetBrains Mono, `tabular-nums`** |
| Body / labels / controls | 16px (1rem) | 400 | 1.5 | Inter (label emphasis via color: Grafito on darker, Gris-500 on secondary) |
| Section / modal heading | 20px (1.25rem) | 400 | 1.25 | Inter (heading emphasis via size + Grafito color, not weight) |
| Page title (H1: "{Proyecto} · Unidades") | 28px (1.75rem) | 500 | 1.2 | **Space Grotesk (brand-sanctioned display weight)** |

**Weight system — exactly two distinct weight values:**

- **400** — every Inter role (grid, body, labels, controls, section/modal headings) and JetBrains Mono money figures. JetBrains Mono is a new *family* at the same 400 weight — it adds no new weight value.
- **500** — the H1 page title only, in Space Grotesk. This is the display face's brand-sanctioned display weight (brand-book §Tipografía: *"Space Grotesk (700/500) para titulares"*); 500 (not 700) because this is an in-panel data screen, not a marketing hero.

Two weight values total (400 and 500). No other weights or families are permitted in this phase.

**Money rendering rule (non-negotiable):** integer USD, es-AR thousands separator `.` → `USD 185.000`. Always JetBrains Mono + `tabular-nums` so columns align. Empty price (no `unit_price` row yet) renders `—` (em dash, `--gris-500`), never `0` and never `USD 0`. Never a decimal/float anywhere.

## Color

Panel is a light-surface data tool — the brand permits this explicitly ("el panel de autogestión puede ser claro", brand-book §Color). Marketing surfaces stay dark-first; this grid does not.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | Hormigón `#F2EFE9` (app canvas) + Blanco `#FFFFFF` (grid rows, modals, cards) | Backgrounds and the grid canvas |
| Secondary (30%) | Gris-100 `#E5E2DB` (borders, sticky header row, toolbar bg) · Gris-500 `#6B7480` (ref/secondary text) · Grafito `#14181E` (primary text) | Structure, dividers, non-primary text |
| Accent (10%) | Cobre `#D98A4F` | See reserved list below |
| Destructive / error | Vendido `#D65454` | See below |

**Accent (cobre) reserved for — explicit list:**
- Primary action buttons: `Exportar a Excel`, `Importar Excel`, `Editar precios en lote`, `Previsualizar cambios`, `Aplicar cambios`, `Confirmar`.
- The focused/editing price-cell ring (2px cobre outline).
- The selection-count bar accent (active-state emphasis when ≥1 row selected).

Cobre is **never** a page/large-area background, **never** on links, **never** on estado badges. One cobre emphasis per primary flow.

**Destructive/error (vendido red `#D65454`) used for:** import validation errors and the invalid-rows list, the cell save-error state, and the `vendido` estado badge. There is no red "delete" button in this phase — the irreversible money operations (bulk apply, import apply) are cobre primary actions **gated by a mandatory preview**, not red.

**Semantic unit-state colors (reserved to estado, not part of the 10% accent):** disponible `#2FA26E` · reservado `#E3A63C` · vendido `#D65454`. Rendered as a filled status dot + label.

> ⚠ **Warm-color adjacency:** reservado amber `#E3A63C` and accent cobre `#D98A4F` are close. Mitigation: estado always renders as **dot + text** (never a bare fill and never as a button), and no cobre button sits adjacent to an estado cell without that dot affordance. Estado is status, cobre is action — keep them visually distinct.

Links (e.g. "← Proyectos" breadcrumb): Blueprint `#4C7DF0` (brand: "detalle técnico, links, datos").

## Component Inventory

**Primary focal point (visual anchor):** on the units-grid screen the **price columns (Financiado USD / Contado USD) are the primary visual anchor** — JetBrains Mono `tabular-nums` figures with aligned decimal columns draw the eye first, and the cobre focus ring on an editing price cell is the single strongest accent on the screen. Everything else (ref columns in Gris-500, estado dots, toolbar) is deliberately lower-contrast so money reads as the priority. Executors must preserve this hierarchy: no other element may out-weight the price columns visually.

## Interaction Contracts

**Price cell state machine (GRID-01):**
`idle` → (hover: cursor + subtle `--gris-100` bg) → click → `editing` (native numeric input, JetBrains Mono, 2px cobre focus ring, current value pre-filled) → **Enter or blur** → `saving` (input disabled, spinner) → `saved` (brief green-tint flash, reverts to idle) **or** `error` (vendido-red border + `No se pudo guardar. Reintentá.`; original value restored on Escape/dismiss). **Escape** during `editing` cancels without saving. Only whole-USD input accepted; parse rejects non-integers before the mutation.

**Estado cell (GRID-02):** native `<select>` (or ARIA listbox) with the 3 enum options, each shown as colored dot + label; on change → `saving` → `saved`. Individual only (no bulk estado — D-12).

**Selection → bulk (D-04, D-12, D-13):** row checkboxes build a selection; header checkbox toggles all visible rows (indeterminate when partial). Selection bar shows the zero-one-many count. Bulk edit **always** routes through the preview modal (viejo → nuevo per unit) before any write — no direct apply.

**Every successful mutation (inline / bulk / import apply)** triggers the GRID-07 on-demand ISR revalidation of the public picker/cotizador; surface it in the success copy ("La web pública ya está actualizada"). The exact revalidation mechanism is research+planning (D-14) — the UI contract is only that success messaging asserts instant public reflection.

## Import Flow (the critical surface — GRID-04/05/07/08)

Four steps in one modal/wizard. All-or-nothing apply in a single transaction (D-08).

**Step 1 — Upload.** Dropzone + file input. States: `idle` · `dragover` · `file-selected` · `parsing` · `parse-error` (bad/unreadable file → parse-error copy above). Accept only the canonical single-sheet template (D-09).

**Step 2 — Validation report (dry-run, D-06/D-07).** Summary bar top: `{N} nuevas · {N} con cambios · {N} sin cambios · {N} con errores`. If **errors > 0**: render the invalid-rows list (row nº + es-AR reason, scrollable), and **`Aplicar cambios` is disabled** with the blocked-hint copy. The user cannot proceed to apply until the file is 100% valid.

**Step 3 — Diff preview (only when errors = 0).** Three classified groups:
- **Nuevas** — list of new units.
- **Con cambios** — **field-by-field viejo → nuevo** (D-06, `specifics`): old value in Gris-500 with strikethrough, new value in Grafito, both JetBrains Mono for prices, separated by `→`. Never apply a money change blind.
- **Sin cambios** — collapsed count (expandable).

**Step 4 — Confirm.** `Aplicar cambios` (cobre primary) with the all-or-nothing confirmation copy + `Cancelar`. States: `preview` → `applying` (disabled + spinner) → `success` (applied count + web-pública-updated) **or** `error` (nothing was written — restate all-or-nothing; no partial state).

Diff and error lists must scroll within the modal (overflow) without pushing the summary bar or action buttons out of view.
